Introduction to Single-Server Setup

A journey of a thousand miles begins with a single step. When designing a complex system, it is crucial to start simple. Before we add redundancy, partitioning, or failover, we must understand the core flow of a system that serves a single user.

Imagine a basic client-server setup: everything is running on one server. The web app, the database, and the application logic are all co-located on a single machine.

The Single Server Setup

Figure 1: Single Server Diagram - A minimal visual flow. (Placeholder for Excalidraw-style asset)

The flow is straightforward: Users access websites through domain names (e.g., mysite.com). When the request is sent, the Domain Name System (DNS) returns the IP address, and Hypertext Transfer Protocol (HTTP) requests are sent directly to your web server. The web server then returns an HTML page or JSON response.

Incremental Growth: Scaling the Data Tier

As your user base grows, this setup will quickly break. The first major bottleneck is often the database. It shares CPU, RAM, and disk I/O with the web application. When the database gets overloaded, your entire service slows down.

The logical first step in **incremental growth** is separating the data tier from the web application tier.

Figure 2: Separated Architecture Diagram - Improving performance by isolating components.

By moving the database to its own server, we improve performance and allow them to be scaled independently. We have introduced our first layer of architectural sophistication.
